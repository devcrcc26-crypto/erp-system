# Approvals Inbox

Every request that needs a decision (leave, overtime, per diem, purchases and more) goes through **Approvals**. Here you follow your own requests, and approvers approve, reject, return or conditionally approve the requests that are waiting for them.

**Who does what**

| Role | What you can do |
| --- | --- |
| Employee (everyone) | Start requests, follow them in **My Requests**, continue drafts, and resubmit returned requests. |
| Approvers (managers, leads, HR, management) | Act on requests in **Pending My Action**: approve, reject, return or conditionally approve. |
| HR and management | See every request in **All Requests**. |
| HR Manager, System Administrator | Reassign a pending step to a different approver. |

**Where to find it**
- Click **Approvals** in the left menu. The badge shows how many requests are waiting for you.
- Click **New Request** in the left menu to start a request.

---

## How to start a new request

*(All employees)*

1. Click **New Request** in the left menu. This opens the **What would you like to request?** picker.
2. Search for a request type in **Search request types**, or pick one from **Recently used**.
3. Click the request type. The form for that type opens.
4. Fill in the required fields. Missing required fields show *"Please fill in all required fields"*.
5. Click **Submit request**.

> **What happens next:** The request appears in your **My Requests** tab and moves into the approval chain. You get the notification *"Approval request submitted"*. Some request types (for example leave and overtime) have their own form in the module. The picker links you to it.

## How to find the requests waiting for you

*(All employees)*

1. Click **Approvals** in the left menu.
2. Click **Pending My Action**. These are requests where you are the approver for the current step.
3. Use the search box, **Filter by category**, the date range or the status filter to narrow the list.
4. Click a request to open it.

> **Tabs:**
> - **Pending My Action**: requests waiting for your decision.
> - **My Requests**: requests you submitted.
> - **All Requests**: every request you can see (HR and above).
> - **My Drafts**: requests you started but did not submit. Click a draft to continue it.
>
> The list opens on **All Requests** for HR users, and on **My Requests** for everyone else.


---

## How to review a request before deciding

1. Open the request from the list.
2. Read the request details, attached files and the **Approval chain** (the steps and who is at each step).
3. Check the **Current tier** badge. It shows the step that is waiting now.
4. Read any notes in the **Resubmission / response history** section.

> **Note:** Only the approver of the **current** step can act. Other people see the request but cannot approve it.

---

## How to approve a request

*(The approver of the current step)*

1. Open the request.
2. Click **Approve**.
3. Add an optional note under **Note (optional)**.
4. Click **Approve**.

> **What happens next:**
> - If there are more steps, the request moves to the next approver. That approver receives *"Approval required"*.
> - If this was the last step, the request is **Approved**. The requester receives *"Approved"*, and the request's module updates (for example, leave days are recorded as used).


---

## How to reject a request

*(The approver of the current step)*

1. Open the request.
2. Click **Reject**.
3. Enter the **Rejection reason** when asked.
4. Click **Reject** to confirm.

> **What happens next:** The request is **Rejected** and closed. This cannot be undone. The requester receives *"Rejected"* with your reason. To try again, the requester must submit a new request.

---

## How to return a request for changes

*(The approver of the current step)*

Use **Return** when the request is fixable and the requester should amend it, rather than when it should be refused.

1. Open the request.
2. Click **Return**.
3. Enter a **Note for submitter** explaining what must change.
4. Click **Return** to confirm.

> **What happens next:** The request is **Returned**. The requester receives *"Approval returned"* with your note. The requester updates the request and resubmits it (see *How to resubmit a returned request* below). When resubmitted, the request goes back to the first approver.

---

## How to conditionally approve a request

*(The approver of the current step)*

Use a condition when you approve in principle but something must be confirmed first.

1. Open the request.
2. Click **Conditionally Approve**.
3. Enter the **Condition** text (required). It describes what must be resolved.
4. Click **Submit**.

> **What happens next:**
> - The request stays at your step with the condition attached. You cannot approve, reject or return it until the condition is resolved. The dialog and banner say *"Resolve all conditions before taking action."*
> - The requester receives *"Condition response"* notifications and can respond to the condition with a **Response** note and optional files.
> - When the condition is resolved, click **Resolve** to mark it done. Then you can approve, reject or return the request as normal.

---

## How to reassign a pending step

*(HR Manager and System Administrator only)*

1. Open the request.
2. In the approval chain, find the pending step and click **Reassign**.
3. Choose the **New approver**.
4. Click **Reassign**.

> **Rules:** Only pending steps can be reassigned. The new approver receives *"Approval required"* for that step.

---

## How to approve or return on behalf of someone

*(Full-access roles only; shown when the request allows it)*

If you are not the current approver but have on-behalf rights for that request, the request shows **Approve on behalf** or **Return on behalf**.

> **What happens next:** The action is recorded as taken on behalf of the approver. The approver receives *"Approved on your behalf"* or *"Returned on your behalf"*.

---

## How to resubmit a returned request

*(The requester)*

1. You receive *"Approval returned"* with the approver's note.
2. Open the request from **Approvals**. The **Returned** banner says *"This request was returned"* and *"Please make changes and resubmit."*
3. Use the **Resubmit** panel. Add a response note and attach files if needed.
4. Click **Resubmit**.

> **What happens next:** The request goes back to the first approver, who receives *"Resubmitted for approval"*. The earlier notes stay in the **Resubmission / response history**.
>
> **Note:** For leave and overtime, edit the request in its own module first. Then resubmit it from here. For overtime, you can also use **Submit Sheet** in the sheet itself.

## Statuses

| Status | Meaning |
|---|---|
| Pending | Waiting for the current approver. |
| In Review | Being reviewed by an approver. |
| Returned | Sent back to the requester for changes. |
| Approved | Fully approved. |
| Rejected | Refused and closed. |
| Cancelled | Cancelled by the requester or HR. |

**Waiting status:** each request shows what it is waiting for, for example *"Returned - update and resubmit to continue"* or *"No active approval actions"*.

---

## Who approves

Approval steps are set by the request type, and most follow the org chart:

- **Standard employee:** their **Reports to** manager, then the **HR Manager**.
- **Discipline Lead:** the **Department Head** (if assigned), then the **HR Manager**.
- **Department Head:** the **General Manager**, then the **HR Manager**.
- **HR staff:** the **HR Manager**.
- **HR Manager:** the **General Manager**.
- **General Manager, Managing Director, System Administrator:** no approval chain. Requests are approved on submit.

Some request types use their own chain. The chain is always shown on the request.

---

## Tips

- Check **Pending My Action** each day. The **Approvals** badge in the left menu counts what is waiting for you.
- Put a clear note on a **Return** or **Reject**. It is sent to the requester.
- Resolve conditions before you approve. The approve button stays blocked while a condition is open.
- If a request is stuck at a step whose approver has left, ask HR to reassign it.
